# 2026-08-02 — the public-demo spec reached a settings bin D12 does not have, and stopped there

**Two small decisions about a demo's reset interval collided with D12's two-bin model and produced a gap neither could absorb: a deploy-time value the UI must render but no visitor may edit. It was proposed, filed and left unbuilt, and the PR carrying it was split from the spec so the spec would not wait on a seat that was unavailable.**

The surface review quince#444 ruled must come first merged as quince#467, which unblocked the mode's own spec — program doc §8, a rung starts from a spec, reviewed before any code exists.

Most of the spec is recording what was already ruled: a separate `--public-demo` rather than a `--demo` modifier, the password is `demo`, and presetting it *is* what makes it immutable, since `POST /api/auth/setup` already refuses once a password exists.

**Two decisions were actually new, and both looked trivial.** First, the reset is a process restart performed from outside the process — `--demo` already deletes its DB and config at start *and* at exit, so a restart is a complete reset with no new code, and quince gets no timer. Second, the interval is configuration rather than a constant, because the Operator explicitly left the value unruled and a spec that wrote thirty minutes would have been deciding it.

Together they produce a value the app does not act on and only *renders*. And that is where D12 runs out. D12 sorts settings into deployment topology in env, and **every other setting** in `config.yml`, editable in the UI. As a `config.yml` key the interval is editable by every visitor — in this mode everyone is authenticated by design and `PUT /api/config` is live — so a visitor could change the displayed promise without changing the restart, leaving the UI stating something false. That is a state-honesty failure wearing a config-tidiness costume. As an env var it is a third bin, and the precedent widens `QUINCE_*` from a principled short list to anything awkward.

**The third option is the interesting one, and it is the weakest.** Say no interval at all — *"this demo resets periodically"*. No configuration, no gap, and an unannounced destructive reset for a visitor mid-click. Which is precisely what *no silent caps or fallbacks* exists to forbid, so the cheapest escape from the gap is the one the rules close.

Proposed rather than decided, filed as quince#470, written as a `PROPOSED (gap)` block into the stack doc, and not built on. Only story 6 of seven depends on it.

**The split is the part worth recording.** The gap protocol wants the block in the affected canon doc, and `/docs/quince.stack.md` is code-owner-owned by `@novkostya` — an architect verdict structurally cannot satisfy it, because an App cannot be a code owner. So a single PR carrying both the spec and the canon block would have parked the spec behind the one seat that was unavailable overnight. Splitting cost one extra PR and nothing else: quince#470 carries the full gap text and so does the spec's own gap section, so nothing became less discoverable. quince#471 is the spec, quince#472 is the canon block, and only the second has to wait.

**And a correction against myself, recorded because it is the more useful half.** Between the review merging and this spec, I started building the fix for quince#463 — the setup-route amplifier the review found. It is a derived task and the fix is good: green, mutation-checked against a pre-fix mutant, and the burst that took 9 MB to 2063 MB stays flat at 138 MB with the 409 path at 0.2 ms instead of ~85 ms. It was also **out of scope**, and my own plan had said fixes wait for the review to be approved — I talked myself past that the moment the approval landed, reasoning that an approved review licenses acting on its findings. It does not; it licenses filing them, which had already happened. The branch exists locally at `r9/setup-no-hash-when-configured` and was never pushed, so the overreach cost nothing but the detour. The failure mode is worth naming: **an approval feels like permission for whatever comes next**, and the thing that stopped it was being told, not noticing.
